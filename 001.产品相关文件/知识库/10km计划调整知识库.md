# 10km计划调整知识库

## 用途

本库用于用户完成一次训练并提交反馈后，调整未来 1–3 次训练。默认先调整下一次；只有反馈显示问题持续或风险较高时，才扩大到后续训练或当前周。不重新生成完整 8–12 周计划。

## 用户侧可用输入

用户反馈页固定提供以下字段：

- `subjective`：主观疲劳程度，1–5 分。
- `physical`：身体状态感受，1–5 分。
- `pain`：疼痛不适程度，1–5 分。
- `discomfort`：是否有局部不适或疼痛，`true/false`。
- `discomfortParts`：不适部位，可为空数组。
- `note`：用户补充训练感受，可为空。
- `current_plan`：当前训练计划，包含当前训练安排和课程信息。
- `completed`：完成训练页记录的实际训练数据，包括 `distanceKm`（实际距离）、`durationMin`（实际时长）和 `pace`（平均配速），可能为空。

用户侧没有独立提供实际 RPE、睡眠、晨脉或疾病症状。缺训周数也不是反馈页的独立输入；如需判断，只能依据 `current_plan` 中的训练状态或 `note` 明确说明。实际完成距离、时长和配速应优先使用 `completed` 中的数据，不得自行推断。

## 分析状态字段

反馈分析节点应将输入转换为以下固定状态：

```text
completion=completed|partial|missed|unknown
fatigue=low|moderate|high|severe
physical=good|normal|poor
pain=none|mild|moderate|severe
discomfort=true|false
parts=部位列表或none
action=progress|maintain|reduce|recovery|rest|medical_review
scope=none|next_1|next_2|next_3|current_week
```

评分映射：

- `subjective` 1–2：`fatigue=low`；3：`moderate`；4：`high`；5：`severe`。
- `physical` 1–2：`physical=good`；3：`normal`；4–5：`poor`。
- `pain` 1：`pain=none`；2：`mild`；3：`moderate`；4–5：`severe`。
- 明确有不适或 `pain>=3` 时，`discomfort=true`；不得递进训练；若伴随明显疼痛或加重，执行休息或医疗评估。
- `note` 明确写“未完成、只完成一部分、提前停止”时，`completion=partial`；明确写“未训练”时，`completion=missed`；没有说明时为 `unknown`。

## 规则优先级

安全 > 医疗评估 > 休息 > 降负荷 > 恢复课 > 保持 > 小步递进。命中多条规则时只执行优先级最高的一条。

## 调整规则

### R-PAIN-SEVERE 明显疼痛或疼痛加重

- 触发：`pain=moderate/severe`，或 `discomfort=true` 且 `note` 描述跑步中加重、动作改变、刺痛或关节痛。
- 动作：未来 2–3 次训练；必要时覆盖当前周，暂停质量课和长距离；若仍有症状，建议寻求专业评估。
- `action=rest` 或 `medical_review`；`scope=next_2|next_3|current_week`。

### R-PAIN-MILD 轻微酸痛

- 触发：`pain=mild`，且没有疼痛加重、动作改变或明显不适描述。
- 动作：未来 1–2 次改为恢复跑或低强度轻松跑，缩短时长，不增加训练量。
- `action=recovery`；`scope=next_1|next_2`。

### R-DISCOMFORT 局部不适

- 触发：`discomfort=true`，但疼痛评分未达到明显疼痛，且 `note` 未描述加重。
- 动作：未来 1–2 次保持或降低负荷，不安排质量课；训练中不适加重则停止。
- `action=reduce`；`scope=next_1|next_2`。

### R-FATIGUE-SEVERE 疲劳过高

- 触发：`fatigue=severe`，或 `physical=poor` 且 `note` 明确描述明显疲劳、恢复差或身体沉重。
- 动作：未来 2–3 次安排休息或恢复活动，不安排质量课和长距离。
- `action=rest`；`scope=next_2|next_3|current_week`。

### R-FATIGUE-HIGH 高疲劳

- 触发：`fatigue=high` 或 `physical=poor`，且没有明显疼痛。
- 动作：未来 1–2 次降为恢复跑或轻松跑，缩短时长，不递进。
- `action=recovery`；`scope=next_1|next_2`。

### R-PARTIAL 部分完成

- 触发：`completion=partial`，且没有明显疼痛或高风险信号。
- 动作：未来 1–2 次重复或降一档，不能补课，不能把两次训练合并。
- `action=reduce` 或 `maintain`；`scope=next_1|next_2`。

### R-MAINTAIN 正常完成但状态一般

- 触发：`completion=completed`，`fatigue=moderate` 或 `physical=normal`，没有疼痛和局部不适。
- 动作：保持当前计划；如需输出课程，返回下一次原课程。
- `action=maintain`；`scope=next_1`。

### R-PROGRESS 正常完成且状态良好

- 触发：`completion=completed`，`fatigue=low`，`physical=good`，`pain=none`，`discomfort=false`。
- 动作：未来 1 次只允许从首次计划知识库中选择小步递进课程；不增加高强度课程数量。
- `action=progress`；`scope=next_1`。

### R-UNKNOWN 信息不足

- 触发：`completion=unknown` 或反馈字段缺失。
- 动作：未来 1 次保持或降低负荷，不主动增加训练量；不得编造用户未提供的训练数据。
- `action=maintain` 或 `reduce`；`scope=next_1`。

## 课程选择限制

1. 只能从首次生成知识库中选择已有课程。
2. 不得自行创造课程名称、强度区间、课程结构或配速。
3. 降负荷优先选择同类别的短时课程；没有合适课程时选择恢复跑或休息。
4. 只调整受影响的未来课程；未受影响课程保持原计划，不重做完整周期。
5. 出现明显疼痛、疾病风险或高疲劳时，不安排质量课、冲刺课或长距离课。
6. 输出的课程必须保留知识库中的课程结构、时长或距离、RPE、谈话测试、训练目的、前置条件和降级规则。

## 检索查询格式

反馈分析节点输出以下固定键值文本供本库检索：

```text
completion=...
fatigue=...
physical=...
pain=...
discomfort=...
parts=...
action=...
scope=...
```

检索优先匹配规则 ID、触发条件和 action。不要使用整段自然语言反馈作为检索条件。

## 输出要求

最终调整结果应为合法 JSON，至少包含：

```json
{
  "status": "maintain|progress|reduce|recovery|rest|medical_review",
  "adjustmentScope": "none|next_1|next_2|next_3|current_week",
  "ruleId": "R-规则编号",
  "reason": "基于用户反馈的简短原因",
  "workouts": [
    {
      "week": 1,
      "day": 1,
      "type": "知识库中的课程类型",
      "durationMin": 30,
      "distanceKm": null,
      "intensity": "知识库中的强度",
      "talkTest": "知识库中的谈话测试",
      "note": "训练目的、前置条件和降级规则"
    }
  ],
  "planChanges": []
}
```

本知识库用于产品计划调整，不构成医疗诊断或伤后康复方案。
